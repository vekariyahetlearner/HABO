# HeatMaps mobile builds

HeatMaps now ships as an offline-first Capacitor application for Android and iOS. The native shell packages the same static Next.js bundle used by the local web app; habits, daily progress, journals, reviews, settings, and custom audio remain on the device through WebView `localStorage` and IndexedDB.

## Build flow

```bash
npm install
npm run cap:sync
```

`cap:sync` creates a static Next.js export in `out/` and copies it into both native projects. The export build temporarily disables `src/proxy.ts`, because Next.js static exports cannot include a server Proxy; its protections that apply to local content are mirrored in `src/app/layout.tsx` as a CSP meta policy. The build script restores the Proxy before it exits.

For day-to-day native development:

```bash
npm run cap:android
npm run cap:ios
```

Open Android in Android Studio and iOS in Xcode. Do not edit `android/app/src/main/assets/public` or `ios/App/App/public` directly: they are generated by `cap:sync`.

## Release prerequisites

- Android: Android Studio, an installed Android SDK matching `compileSdk 35`, and JDK 21. Build and sign a release AAB in Android Studio with the production signing key.
- iOS: macOS, Xcode, CocoaPods, an Apple Developer signing team, and a physical-device/simulator test. The current project targets iOS 14.0 and later.
- Both: test a fresh install, upgrade from the previous build, offline launch, background/resume, storage restore, custom-audio playback, and backup/restore on a real device.

## Data boundary

Data is device-local and is not synchronized between the browser and a native app, nor between devices. A user must export a backup before clearing app storage, uninstalling, changing devices, or moving between web and native. Custom audio is device-local IndexedDB data and is intentionally not part of the JSON backup.

## Versioning

Before any store release, increase all of these together:

- `android/app/build.gradle`: `versionCode` and `versionName`
- `ios/App/App.xcodeproj/project.pbxproj`: `CURRENT_PROJECT_VERSION` and `MARKETING_VERSION`
- `package.json`: app version

The package identifier is `com.heatmaps.app`; reserve/verify it in Google Play Console and App Store Connect before publishing.
